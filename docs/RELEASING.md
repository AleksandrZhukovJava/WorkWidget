# Процесс: релизы, версии, откат

Коротко о том, как проект живёт на GitHub.

## Ветки

- `main` — стабильная, всегда собирается (гейт — workflow **CI**).
- Работа — в коротких ветках `feat/...`, `fix/...` → Pull Request → merge в `main`.
  Даже в одиночку PR полезен: на нём прогоняется CI (typecheck + сборка).

## Версии

Версия хранится в `package.json` (`version`) и отражается в теге `vX.Y.Z`.
Семантика: `patch` — фиксы, `minor` — новые функции, `major` — несовместимые изменения.

## Выпуск релиза

1. Убедиться, что `main` зелёный (CI прошёл).
2. Поднять версию и поставить тег одной командой:
   ```
   npm run release:patch   # или release:minor / release:major
   ```
   Это делает коммит `chore(release): vX.Y.Z` и git-тег `vX.Y.Z`.
3. Запушить коммит вместе с тегом:
   ```
   git push --follow-tags
   ```
4. Пуш тега `v*` запускает workflow **Release**: в облаке GitHub собирается
   Windows-установщик и публикуется **GitHub Release** с ассетами:
   - `Jira Widget-X.Y.Z-setup.exe` — установщик,
   - `latest.yml` + `*.blockmap` — фид автообновления (нужен electron-updater).
5. (По желанию) отредактировать текст релиза на странице Releases.

Ничего собирать локально не нужно — сборка воспроизводимо идёт в CI.

## Автообновление

Установленный виджет при запуске (и раз в 6 часов) проверяет GitHub Releases
через `electron-updater`, скачивает новую версию в фоне и ставит её при выходе.
Работает только в установленном (packaged) приложении, в dev-режиме отключено.
Фид берётся из `publish` в `electron-builder.yml` (owner/repo).

## Откат к версии

- **Код**: `git checkout vX.Y.Z` (посмотреть/собрать старую версию) или
  `git switch -c fix-from-vX.Y.Z vX.Y.Z` (ветка от тега), либо `git revert <commit>`.
- **Установленное приложение**: скачать `*-setup.exe` нужной версии со страницы
  её Release и переустановить.

## Задачи

- Баги/идеи — через **Issues** (есть шаблоны). Метки — из `.github/labels.yml`
  (синхронизируются workflow **Labels**: Actions → Run workflow).
- Под каждый релиз — **Milestone** `vX.Y.Z` (создаётся вручную в вебе:
  Issues → Milestones → New milestone), задачи привязываются к нему.

## Локальная сборка (для проверки, без публикации)

```
set CSC_IDENTITY_AUTO_DISCOVERY=false
npm run build
```
Собирает установщик в `dist/` и НЕ публикует (флаг `--publish` не передаётся).
